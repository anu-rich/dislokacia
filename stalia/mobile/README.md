# Stalia для Android и iPhone

Это тот же калькулятор, упакованный как приложение (Capacitor 8). Код один: всё, что меняется на сайте, попадает в приложение следующей сборкой.

## Три способа дать людям приложение

| Способ | Что нужно | Состояние |
|---|---|---|
| **Установка с сайта** (Android и iPhone) | Только опубликованный сайт | Работает. Проверено в браузере: ставится, открывается без интернета |
| **Android: APK и Google Play** | Аккаунт разработчика Google, 25 $ один раз | APK собирается и собран; на реальном телефоне я запустить его не мог — проверьте установкой |
| **iPhone: App Store** | Mac с Xcode и Apple Developer, 99 $ в год | Проект создан, но ни разу не собирался (нужен Mac) |

### Установка с сайта — уже сейчас

На телефоне открыть калькулятор и нажать «Установить приложение»:

- Android (Chrome): меню ⋮ → «Установить приложение».
- iPhone (Safari): «Поделиться» → «На экран „Домой“».

Иконка появляется на главном экране, калькулятор открывается на весь экран и работает без интернета. Магазины и аккаунты не нужны.

## Сборка Android

Нужны Node 22+, JDK 21 и Android SDK (платформа 36).

```bash
cd stalia/mobile
npm install
npm run android:apk
# готовый файл: android/app/build/outputs/apk/release/app-release.apk
```

Этот файл можно переслать на телефон и установить (Android попросит разрешить установку из этого источника). Он подписан вашим постоянным ключом из `android/stalia-upload.jks` — тем же, что и пакет для магазина, поэтому следующие версии ставятся поверх без удаления. Без файла ключа и `android/keystore.properties` рядом сборка выйдет неподписанной и не установится.

Сборки до 1.4.0 включительно были подписаны временным тестовым ключом. Если такая стоит на телефоне, её нужно один раз удалить перед установкой 1.5.0 (сохранённые расчёты и ключ Pro на этом телефоне при удалении пропадут — ключ вводится заново).

`npm run android:debug` собирает отладочный вариант на тестовом ключе — для проверки на своём телефоне, не для раздачи.

### Публикация в Google Play

Правила сверены со справкой Google 12 ноября 2026 года. Они меняются: если в Play Console написано иначе — верьте ей.

**Что понадобится от вас.** Аккаунт Google, возраст от 18 лет, банковская карта на ваше имя (25 $ один раз, не возвращаются), удостоверение личности, телефон на Android. Казахстан есть в списке стран, где можно зарегистрироваться.

**Что будет видно всем.** У личного аккаунта Google показывает на странице приложения ваше настоящее имя, страну и e-mail разработчика; полный адрес — только если продавать через Google Play. У аккаунта организации показываются её название, адрес, e-mail и телефон. Решите это до регистрации.

**Личный или организация.** Личный аккаунт открывается быстрее, но перед публикацией обязан пройти закрытое тестирование (шаг 5). Организации (ТОО, ИП) нужен номер D-U-N-S — его выдаёт Dun & Bradstreet бесплатно, срок до 30 дней, — зато тестирование не обязательно.

1. **Регистрация.** [play.google.com/console/signup](https://play.google.com/console/signup) → тип аккаунта → публичное имя разработчика (можно «Stalia») → оплата 25 $ → подтверждение личности документом, e-mail и телефона. Для личного аккаунта ещё подтверждается телефон на Android — через приложение Play Console.
2. **Создать приложение.** Create app → название из `marketing/store-listing.md`, язык по умолчанию — английский, тип App, Free.
3. **Анкеты (App content).** Политика конфиденциальности (нужен опубликованный сайт со страницей `privacy.html`), доступ к приложению, реклама, возрастной рейтинг, аудитория, безопасность данных. Готовые ответы — в `marketing/store-listing.md`.
4. **Карточка (Main store listing).** Тексты — там же; значок, баннер и снимки экрана — в `marketing/play/`.
5. **Закрытое тестирование** — для личных аккаунтов, созданных после 13 ноября 2023 года. Testing → Closed testing → создать выпуск, загрузить файл `.aab`, добавить адреса Gmail тестировщиков и разослать им ссылку. Нужно, чтобы минимум 12 человек согласились на участие и не выходили из теста 14 дней подряд. Это самая долгая часть: начните набирать людей сразу.
6. **Заявка на публикацию.** Dashboard → Apply for production: вопросы о том, как набирали тестировщиков, чем они пользовались, что вы исправили. Ответ обычно в течение семи дней.
7. **Выпуск.** Production → Create new release → тот же `.aab` или более новый → страны → отправить на проверку. После одобрения приложение видно всем.
8. **После выхода.** Впишите адрес приложения в `app/config.js` → `apps.android`: на сайте появятся ссылка на магазин и кнопка «Открыть в приложении».

**Файл для магазина.** Google принимает не APK, а пакет `.aab`, подписанный вашим ключом загрузки:

```bash
cd stalia/mobile/android
keytool -genkeypair -v -keystore stalia-upload.jks -alias stalia -keyalg RSA -keysize 2048 -validity 10000
```

Рядом нужен файл `keystore.properties` (в git он не попадает):

```
storeFile=stalia-upload.jks
storePassword=пароль
keyAlias=stalia
keyPassword=пароль
```

Сборка: `npm run android:release` → `android/app/build/outputs/bundle/release/app-release.aab`. При первой загрузке Play Console предложит Play App Signing — соглашайтесь: главный ключ приложения хранит Google, а ваш ключ загрузки при утере можно заменить через поддержку. Файлы `stalia-upload.jks` и `keystore.properties` храните у себя: ими подписывается каждое обновление.

Для каждой новой загрузки увеличивайте `versionCode` и `versionName` в `android/app/build.gradle`. Сборка нацелена на Android 16 (API 36) — это требование Google к новым приложениям с 31 августа 2026 года.

**Риски.**
- Pro оплачивается не через Google. В магазинной сборке нет ни цен, ни ссылок на покупку — только поле для ключа; на таких условиях Google допускает приложения, где купленное на стороне просто используется. Если проверяющий решит иначе, придётся подключать Google Play Billing (комиссия Google) или убрать Pro из приложения.
- Установка APK в обход магазина усложняется: с 30 сентября 2026 года в Бразилии, Индонезии, Сингапуре и Таиланде Android ставит без лишних шагов только приложения подтверждённых разработчиков, в 2027 году это расширяют на весь мир. Регистрация в Play Console — это и есть такое подтверждение.

## «Из документов» в приложении

- В сборке без сервера чтение работает со своим ключом: «Из документов» → «Читать со своим ключом Claude API» → вставить ключ один раз. Ключ хранится только в приложении на этом телефоне.
- Чтобы читать могли и без своего ключа, впишите адрес сервера чтения в `app/config.js` (`ai.endpoint`) и соберите приложение заново: настройки приложение хранит внутри себя.
- Кнопка «Сфотографировать» открывает штатную камеру телефона. Отдельного разрешения на камеру приложение для Android не просит; на iPhone система спросит доступ к камере при первом снимке — текст запроса лежит в `ios/App/App/Info.plist`.
- Чтение PDF встроено в приложение (PDF.js) и работает без интернета; интернет нужен только для самого чтения.
- На настоящем телефоне я это не запускал: проверена веб-часть приложения в эмуляции телефона в браузере.

## Файлы и ссылки в приложении

- **Word, Excel, CSV, файл-копия.** Кнопка создаёт файл и открывает системное «Поделиться»: его можно отправить в мессенджер или почту, сохранить в «Файлы» или на Диск, открыть в Word или Excel. За это отвечает маленький модуль `StaliaSharePlugin.java`; файл лежит во временной папке приложения и заменяется следующим.
- **Ссылка на расчёт.** Кнопки «Отправить ссылку» и «Скопировать ссылку» появляются, когда в `app/config.js` вписан адрес сайта (`siteUrl`): ссылка ведёт на сайт, а расчёт зашит в неё целиком. Без адреса сайта ссылке некуда вести, поэтому в такой сборке этих кнопок нет.
- **Открытие ссылки в приложении.** Приложение откликается на адреса вида `stalia://c/…`. На сайте кнопка «Открыть в приложении» в полоске «Расчёт открыт по ссылке» появляется у посетителей с Android, когда в `app/config.js` → `apps.android` вписан адрес приложения в Google Play: она открывает расчёт в приложении, а если оно не установлено — страницу магазина.
- На настоящем телефоне я всё это не запускал. В браузере проверено, что страница вызывает модуль с правильными данными (`node tests/e2e/export.js`); сам модуль собран вместе с APK. Первым делом проверьте на телефоне: «Excel» → в списке «Поделиться» выбрать мессенджер → файл открывается у получателя.
- В iOS-сборке своего модуля нет: файлы уходят через «Поделиться» самого веб-окна, если система его даёт, иначе кнопок нет. Ссылки с сайта приложение для iPhone пока не открывает.

## Сборка iPhone

Только на Mac:

```bash
cd stalia/mobile
npm install
npm run ios:open        # откроет проект в Xcode
```

В Xcode выбрать свою команду (Team), проверить Bundle Identifier и сделать Product → Archive → загрузить в App Store Connect.

Чего в iOS-сборке пока нет: печати таймшита в PDF (кнопка скрыта). В версии, установленной с сайта через Safari, печать делает сам браузер.

## Что отличает сборку для магазинов

`scripts/build-web.js` копирует калькулятор в `www/` и включает два переключателя:

- `native` — убирает установку с сайта и ссылку на сайт; файлы и ссылки уходят через системное «Поделиться» (см. ниже);
- `store` — убирает цены и ссылки на покупку. Pro включается лицензионным ключом.

Второе сделано из-за правил Google Play и App Store: за цифровые функции внутри приложения нельзя брать оплату в обход их платёжных систем и нельзя вести пользователя на внешнюю оплату. Если захотите продавать подписку прямо в приложении, придётся подключать Google Play Billing и Apple In-App Purchase — магазины берут с этих продаж комиссию.

## Идентификатор приложения

Сейчас это `app.stalia.laytime`. Он становится постоянным после первой публикации, поэтому поменяйте его заранее, если выберете другое название:

- Android: `applicationId` в `android/app/build.gradle` и `appId` в `capacitor.config.json`;
- iPhone: Bundle Identifier в Xcode.

## После изменений в калькуляторе

```bash
npm run sync            # обновить копию калькулятора внутри приложений
npm run android:debug   # или android:release
```

Иконки и заставка лежат в `assets/`; после замены картинок выполните `npm run icons`.
