# Сервер Stalia

Один небольшой сервер, который делает три вещи:

1. **Читает документы** для функции «Из документов»: принимает страницы — уже с закрашенными на устройстве пользователя областями, — передаёт их модели Claude и возвращает прочитанные условия и времена. Ключ Anthropic хранится только здесь, в браузер он не попадает. Страницы и ответы сервер не сохраняет.
2. **Хранит пространства компаний**: общие расчёты с историей версий, участниками, ссылками для контрагентов и обсуждением (`src/space.js`). Расчёты приходят уже зашифрованными в браузере; прочитать их сервер не может.
3. **Отдаёт сам сайт и калькулятор**, если сайт собран в папку `public` (`node ../tools/build-site.js`). Тогда один адрес — это всё сразу: страницы по `/`, сервер по `/api`.

Без сервера калькулятор работает как раньше, чтение доступно в режиме «свой ключ», а пространств нет.

Код чтения общий: `src/reader.js` и `src/prompt.js` работают и на сервере, и в браузере (туда их собирает `node tools/build-reader.js` — запускайте после правок в `src/`).

## Один адрес для всего — рекомендуемый запуск

Cloudflare: сайт, сервер и база в одном месте, бесплатного плана хватает для начала.

```bash
cd stalia
node tools/build-site.js                      # собрать сайт в server/public
cd server
npm install
npx wrangler login
npx wrangler d1 create stalia                 # база для пространств; выданный database_id вписать в wrangler.toml
npx wrangler secret put ANTHROPIC_API_KEY     # только для чтения документов; можно позже
npx wrangler deploy
```

Что получится: адрес вида `https://stalia.<ваше-имя>.workers.dev` — по нему открываются сайт и калькулятор, а чтение и пространства работают без дополнительных настроек: в собранной копии `app/config.js` они уже указывают на `/api` этого же адреса. Свой домен подключается в кабинете Cloudflare.

После любых правок сайта: снова `node tools/build-site.js` и `npx wrangler deploy`.

То же на своём сервере (VPS) без Cloudflare: `node tools/build-site.js`, затем `cd server && npm install && npm start`. Пространства лягут в файл `server/data/space.db` — он должен быть на диске, который переживает перезапуск, и его нужно включить в резервное копирование. На бесплатном Render диск не сохраняется: пространства там потеряются при перезапуске.

Как проверено: вся серверная логика пространств — на SQLite в тестах (`tests/space.test.js`, `tests/space-client.test.js`) и в настоящих браузерах против настоящего сервера (`tests/e2e/space.js`). Точка входа Cloudflare проверена с «двойником» базы D1 поверх SQLite. В само облако Cloudflare я ничего не выкладывал: настоящую D1 сервер увидит впервые при вашем развёртывании.

## Пространства компаний: что хранится и кто что видит

- В базе лежат только идентификаторы, время, роли и зашифрованные блоки. Названия, имена, условия, времена, суммы, комментарии шифруются в браузере (AES-256-GCM). Ключ пространства передаётся только внутри ссылки-приглашения, после знака `#` — эту часть адреса браузеры на сервер не отправляют. У каждого расчёта свой ключ; ссылка для контрагента несёт ключ одного расчёта и больше ничего не открывает.
- Следствие: если человек потерял устройство и у него нет файла восстановления (вкладка «Участники»), доступ восстановить нельзя ни ему, ни вам. Владельцу стоит скачать файл восстановления сразу.
- Роли участников: владелец (люди, приглашения, лицензия, удаление), редактор (расчёты, договоры, ссылки), наблюдатель (чтение и комментарии). Ссылка для контрагента: просмотр, комментарии или правка — правка сохраняется отдельной версией под его именем.
- Каждое сохранение — новая версия; из двух человек, сохраняющих поверх одной и той же версии, проходит один, второй получает сообщение и выбор.
- Новое пространство работает 14 дней (`SPACE_TRIAL_DAYS`), дальше нужна лицензия Pro: владелец вводит ключ во вкладке «Участники». Один ключ — одно пространство. Без лицензии всё остаётся доступным для чтения и выгрузки, но ничего нельзя изменить.
- Ограничения от злоупотреблений: не больше 6 новых пространств в сутки с одного адреса (`SPACES_PER_DAY`), размеры и количества записей ограничены в `src/space.js` (`LIMITS`).
- Владелец может удалить пространство целиком — строки удаляются из базы сразу.

## Что понадобится

1. **Ключ API Anthropic.** [console.anthropic.com](https://console.anthropic.com) → API keys → создать ключ. Пополните баланс и сразу поставьте месячный лимит расходов в настройках организации: это ваш жёсткий предохранитель.
2. **Место, где сервер будет работать.** Ниже два варианта. Оба я описал по общим правилам этих площадок, сам на них не разворачивал: названия кнопок могли измениться.

## Только чтение документов. Вариант А: Render — без командной строки

1. [render.com](https://render.com) → New → Web Service → подключите GitHub-репозиторий продукта.
2. Root Directory: `server`. Build Command: `npm install`. Start Command: `npm start`.
3. В разделе Environment добавьте переменные:
   - `ANTHROPIC_API_KEY` — ваш ключ;
   - `ALLOWED_ORIGINS` — адрес сайта, например `https://stalia.example`;
   - `TRUST_PROXY` — `1`.
4. После развёртывания откройте выданный адрес в браузере. Должно появиться `{"ok":true,"service":"stalia-reader","ready":true,…}`. Если `ready` равно `false`, ключ не подхватился.

На бесплатном плане сервис засыпает без запросов, и первое чтение после паузы идёт заметно дольше. Счётчики лимитов живут в памяти и обнуляются при перезапуске. Для двух бесплатных чтений в день это терпимо, а месячный счёт Pro так не удержать: на бесплатном плане сервис перезапускается после каждой паузы. Если 200 чтений в месяц должны соблюдаться строго, берите вариант Б с хранилищем KV.

## Только чтение документов. Вариант Б: Cloudflare Workers

Те же команды, что в разделе «Один адрес для всего», но без `build-site.js` и без базы: если папки `public` нет, Worker отвечает только как сервер (по корню адреса), а сайт живёт где-то ещё.

Адрес сайта и лимиты задаются в `wrangler.toml`. Чтобы лимиты были общими для всех копий сервера, создайте хранилище: `npx wrangler kv namespace create LIMITS` — и впишите выданный id в `wrangler.toml` (там есть закомментированный блок).

На бесплатном плане Cloudflare жёстко ограничено процессорное время на запрос: чтение многостраничных документов может не уложиться. Тогда нужен платный план.

Worker я проверил в локальной среде Cloudflare (`npx wrangler dev`) с «двойником» модели: чтение проходит, лимиты срабатывают. В само облако Cloudflare я его не выкладывал.

## Подключить к сайту и приложению

В `app/config.js`:

```js
ai: { endpoint: 'https://адрес-вашего-сервера/', maxPages: 20 },   // если сайт на том же адресе: 'https://адрес/api'
space: { endpoint: '' },                                           // пусто — тот же сервер, что и для чтения
```

Если сайт отдаёт сам сервер (раздел «Один адрес для всего»), вписывать ничего не нужно.

Для сайта этого достаточно. Приложение для телефона хранит настройки внутри себя, поэтому APK после этого нужно собрать заново (`mobile/README.md`).

## Настройки

Все задаются переменными окружения; образец — `.env.example`.

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `ANTHROPIC_API_KEY` | — | ключ API; без него чтение выключено |
| `ALLOWED_ORIGINS` | пусто | адреса сайтов, которым разрешено обращаться (через запятую); пусто — любым. Приложения для телефона разрешены всегда |
| `STALIA_MODEL` | `claude-sonnet-5-5` | модель для чтений с лицензией Pro |
| `STALIA_MODEL_FREE` | `claude-haiku-5-5` | модель для бесплатных чтений |
| `STALIA_EFFORT` | `high` | тщательность: `low`, `medium`, `high`, `xhigh`, `max` |
| `FREE_PER_DAY` | `2` | бесплатных чтений в день на посетителя; `0` — чтение только для Pro |
| `PRO_PER_MONTH` | `200` | чтений в календарный месяц на одну лицензию Pro; дневного предела нет |
| `MAX_PAGES` | `20` | страниц в одном чтении (то же число — в `app/config.js`) |
| `MAX_BODY_MB` | `24` | наибольший размер запроса |
| `TRUST_PROXY` | `0` | `1`, если сервер стоит за прокси (Render, nginx): тогда адрес посетителя берётся из заголовка прокси |
| `LS_STORE_ID`, `LS_PRODUCT_IDS` | пусто | магазин Lemon Squeezy, если Pro продаётся через него (те же числа, что в `app/config.js`) |

Чтобы все читали одной моделью, впишите одно и то же имя в `STALIA_MODEL` и `STALIA_MODEL_FREE`.

Других лимитов на сервере нет. Бесплатные чтения ограничены на посетителя, а не на всех вместе: если посетителей или ботов много, чтений будет много. Потолок расходов — месячный лимит в кабинете Anthropic; поставьте его обязательно. Бесплатные чтения выключаются одной настройкой: `FREE_PER_DAY=0`.

Если меняете `PRO_PER_MONTH`, поправьте число и в текстах: строка `pro.f7` в `app/i18n.js` и `app/lang/*.js` и тот же пункт на главных страницах.

## Сколько стоит чтение

Замерено на настоящем API на образцах из `samples/` (ноябрь 2026), тщательность `high`:

| Что читали | Haiku 5.5 | Sonnet 5.5 |
|---|---|---|
| Рекап 2 стр. + два стейтмента (4 страницы) | $0,009, 49 с | $0,09, 23 с |
| То же с замазанными названиями и ставкой | $0,009, 48 с | $0,09, 27 с |
| Один стейтмент (1 страница) | $0,006, 39 с | $0,05, 20 с |

На четыре страницы уходит около 26 тыс. токенов на входе; на выходе — 3–4 тыс. у Sonnet и 9–12 тыс. у Haiku (он дольше рассуждает, поэтому и медленнее). Цены моделей: Haiku $0,10 / $0,50 за миллион токенов на входе / выходе, Sonnet $2 / $10.

Двадцать страниц я не замерял. По тем же ценам это примерно $0,02–0,07 на Haiku и $0,25–0,30 на Sonnet; у Haiku запросы длиннее 100 тыс. токенов считаются по тарифу в пять раз выше, и 20 страниц находятся у этой границы.

## Как проверено

- **Настоящий API.** Вся цепочка — калькулятор в браузере, этот сервер, модель — прогнана с настоящим ключом на образцах: чистый комплект, комплект с замазанными названиями и ставкой, один стейтмент рукописным шрифтом. И Haiku, и Sonnet дали точный результат (демередж 23 841,93 $), замазанное не угадывали, а пометили.
- **Что нашла эта проверка.** API отказался принимать схему ответа как строгий формат («the compiled grammar is too large»). Поэтому схема передаётся модели в инструкции, а сервер сам разбирает ответ и приводит его к форме. Ещё пришлось прямо прописать обычную трактовку простоев для случая, когда чартера нет: без этого Haiku посчитал переход к причалу сталийным временем.
- `npm test` в корне проекта: сервер работает с «двойником» модели. Проверяются запрос к API, лимиты, лицензии, отказы модели, возврат попытки при сбое, разбор неидеальных ответов.
- `node tests/e2e/import.js`: вся цепочка в настоящем браузере с «двойником» модели.
- Worker проверен в локальной среде Cloudflare (`npx wrangler dev`) с «двойником» модели.

Не проверено: настоящие документы, особенно написанные от руки и снятые на телефон (образцы — чистые, рукописный — это шрифт, а не почерк); многостраничные чартеры; развёртывание на Render и в облаке Cloudflare. Первое чтение настоящего документа сверьте с оригиналом.

## Что сервер знает о пользователях

- Страницы и ответ модели не сохраняются. В журнал пишутся время, тариф (free или pro), число страниц, размер запроса, длительность и число токенов.
- Для бесплатного лимита сервер держит в памяти не сам IP-адрес, а его хеш; на следующий день он не нужен.
- Изображения обрабатывает Anthropic на условиях для бизнес-клиентов. На странице `privacy.html` это описано так, как я знаю их политику; перед запуском сверьте с действующей редакцией на их сайте.

## Если меняются ключи лицензий

Сервер проверяет ключи Pro теми же открытыми ключами, что и сайт; их копия лежит в `src/public-keys.js`. Команда `node tools/keygen.js init` обновляет её сама. После этого сервер нужно развернуть заново.
